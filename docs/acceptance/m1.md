## 2. 怎么操作的

## 5. 发现的问题

### 已修（测试先行，已提交，重启后装的是修好的版本）

1. **「改了档案」和「看改动」用的是 Agent 自报的维度，不是真正改了的卡片。** 今天 4 条发现里有 2 条列了没改过的维度，第 1 条点「看改动」打开的「定位」根本没变。现在接口按卡片版本实际引用了哪条发现来算 `changed`，哨报和产品「动态」页都只列真正改了的维度，「看改动」打开第一张真正改了的卡（`28dbd5c`）。
2. **同一条发现里同一篇文章出现两次**（Agent 交了两遍），哨报里出现两个一样的来源胶囊。现在提交时按规范化网址去重，界面上也只显示一个（`28dbd5c`）。
3. **当天失败的产品被暂停后还会被重试**（这次是单产品预算 0 把重试拦下的）。现在重试前先看产品是否仍在跟踪（`d69a19c`）。
4. **宽屏下档案卡片排成四列**，六个维度第二行只有两张、展开一张后又空出一格，和设计（宽屏三列、窄屏两列）不符。现在最多三列、每列至少 300px（`530d7fa`；对比图 `product-expanded-1920.png` → `product-expanded-1920-fixed.png`）。

### 没修，记下来

5. **浏览器兜底开着的代价**（重要）：Playwright MCP 进程和无界面 Chrome 按会话常驻到重启（一天约 5 GB）；所有会话（包括你自己的）都多出一组浏览器工具，其中 `browser_run_code_unsafe` 是 Playwright 自己标明「等同远程代码执行」的工具，调研会话读的是不可信网页，浏览器工具调用也没有经过确认。这是 dsh 实验性浏览器提供方的行为，不是前哨的代码；前哨能做的是跑完一次就让 dsh 释放这个会话（要查 dsh 有没有这样的接口），或干脆只在核查会话里用浏览器。**处理：验收结束时我把这两行改回了关闭**，包还装着，想开时把两行改成 `disabled: false` 重启即可（见 `dev/README.md` 第 6 步）。
6. **I6：「官方」靠 Agent 自报。** Muse 的两条待核查发现把 muse.ai（另一家公司）和英国 ICO 标成了官方来源。若它们核查通过，「官方说自己的事一个来源就够」会让它们只凭这一个来源进哨报。建议按产品的官网域名校验 `isOfficial`（M2）。
7. **新增文字的高亮是逐字比对**，改写过的句子里高亮被切成很多小段（见 `look-change-1440.png`），读起来跳。可以把间隔很小的高亮段合并，或按句子标。
8. **英文界面的单复数**：「Found 1 related articles」「1 products」等。dsh 的语言包不提供复数规则，要逐条改写法。
9. **前哨的会话全进了 dsh 侧栏的「前哨」工作区**：一天十来个（推荐、建档、核查、日更、追问），会把你自己的会话挤下去；目前 7 天后才归档。
10. **追问用的是桌面版标准预设的模型**：这台机器上是本机 Ollama 的 Qwen，首条消息连同标准预设的长系统提示要读 5 分钟以上，宿主等响应头超时后反复重试，实际上答不出来。在会话里把模型切到 DeepSeek 后 3 秒就答了。建议以后追问默认用前哨设置里的模型。另外追问的花费不记进前哨的运行记录和预算（运行记录里那一行是 ¥0）。
11. **暂停的产品**：哨报里「Muse 的新消息核查因预算未完成，明天继续」——它已经暂停，明天其实不会继续；措辞在这种情况下不准（少见）。

### 9.4 发现的问题（没修，记下来）

12. **按第二个赛道筛选哨报时，小豆的卡片上写的还是第一个赛道。** 复现：小豆同时在两个赛道里 → 今日哨报 → 点「手机 AI 助理」筛选 → 4 张小豆的卡片都写「小豆 · Personal Agent」。应该：筛选某个赛道时写那个赛道（不筛选时写两个都行）。原因：卡片只拿产品所在的第一个赛道的名字（`Today.tsx` 第 131 行 `tracks[0]?.name`）。小问题，不影响筛选本身。
13. **同一个产品写法稍有不同，就会变成两个产品。** 前哨认「是不是同一个产品」只看「名字 + 公司」是否完全一样（不分大小写、去掉首尾空格）。今天两个赛道的推荐里就出现了：「千问Go!」和「千问Go」（都是阿里巴巴）、「阶跃 Amoo」和「阶跃Amoo」（都是阶跃星辰），库里各有两条。它们现在都只是候选、没被跟踪，所以没造成后果；但如果你在一个赛道跟踪了「千问Go!」、又在另一个赛道勾了「千问Go」，就会有两份档案、两次完整建档、每天两次日更（花两份钱），也不会走「只补缺的卡」。小豆这次对上了，是因为两次推荐碰巧写得一模一样。另外，推荐时告诉 Agent「已经在跟踪、不用再提交」的名单只有本赛道的产品（`recommend.ts` 第 30 行），新赛道里这一项是「（还没有）」，Agent 不知道别的赛道里已有的写法。建议：比对时去掉空格和标点再比，并把所有赛道里跟踪中的产品（连同写法）告诉推荐 Agent。
