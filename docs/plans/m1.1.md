# 前哨 M1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 四处用到模型的地方（调研、核查、写哨报总结、追问）各自可选 dsh 里能用的任何模型；界面始终中文；修掉验收第 12–14 条；装回桌面版。

**Architecture:** 配置加三个可选模型字段，缺省跟调研模型走；一个纯函数按用途选模型、按提供方定计价方式；宿主新增 `GET models`，向 dsh 的 `ctx.llm.listProviders()` / `listModels()` 要清单；设置页用它做四个下拉框。产品认定改为比较统一处理后的「名字＋公司」。

**Tech Stack:** 同 M1：TypeScript、React 19、node:sqlite、vitest、tsdown；dsh 0.2.3-alpha.2。

**Spec:** `docs/m1.1-设计.md`（本次改动），主设计 `docs/设计文档.md`。

## Global Constraints

- M1 的全局约束全部照旧：`docs/plans/m1-core.md` 的 Global Constraints 一节（名字、样式、测试、提交规则逐字适用），SDD 工作区里另有副本 `.superpowers/sdd/m1-core/global-constraints.md`。
- 配置字段名固定：`model`（调研，沿用）、`verifyModel`、`briefModel`、`followupModel`；后三个缺省或 null＝跟调研一样；四个都是 volatile（下一次调用生效，不重启）。
- 用途名固定：`'research' | 'verify' | 'brief' | 'followup'`。推荐、建档、日更都属于 `research`。
- 计价方式固定三种：`'metered'`（按价格表）、`'local'`（¥0）、`'subscription'`（¥0）。判定：提供方 id 或名称匹配 `/ollama|lm-?studio|llama\.?cpp|local/i` → `local`；提供方 id 为 `anthropic` → `subscription`；其余 → `metered`（用前哨价格表，DeepSeek 以外的也先按它估算）。
- 新文案逐字：「调研（推荐·建档·日更）」「核查」「写哨报总结」「追问」「跟调研一样」「DeepSeek Harness 的默认模型」「当前不可用」「读取失败」「已在{tracks}跟踪 · 只补缺的维度」；设置页提示两句：「要用 Claude 订阅：先在 DeepSeek Harness 的模型设置里添加 Anthropic，用 Claude Pro/Max 登录，它就会出现在这里。」「本机模型和 Claude 订阅记 ¥0，不占每日预算；用 Anthropic 按量付费的 API key 时，这部分花费前哨不记。」
- 界面始终中文：注册词典时中、英两个位置都给中文词典；英文那一列保留不删。
- `pnpm check` 全绿才算任务完成；每个任务一个或几个提交，信息末尾带 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。

## Review Focus

1. **存过的模型现在列不出来**（Ollama 没开、Claude 退出登录）→ 设置页照样显示它并标「当前不可用」，保存其他字段时不把它冲掉；调研照用它、失败时给出提供方的错误，不悄悄换模型。测试在 Task 5（`settings.spec.tsx`）和 Task 4（`runner.spec.ts`）。
2. **某个提供方列模型时卡住或报错** → `GET models` 5 秒内返回，那一组 `error: '读取失败'`，其他组照常。测试在 Task 4（`dsh-model.spec.ts`）。
3. **老配置只有 `model`** → 四处都用它；追问不再用桌面版默认模型。测试在 Task 4（`runtime.spec.ts`、`followup.spec.ts`）。
4. **「千问Go!」已在 A 赛道跟踪，B 赛道的候选写成「千问Go」被勾上** → 开始跟踪时把已跟踪的那个加进 B，不新建、不重新建档，只补缺的卡；每天只跑一次日更。测试在 Task 2（`api.spec.ts`、`repo.spec.ts`）。
5. **本机或订阅模型做的调研** → 记 ¥0、不占预算；同一天 DeepSeek 的花费照常累计、照常被预算拦。测试在 Task 4（`cost.spec.ts`、`runner.spec.ts`）。
