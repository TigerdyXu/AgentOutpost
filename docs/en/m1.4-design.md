# Outpost M1.4 design: installs and runs without the install script

> 2026-11-27. The user wants more people to know about Outpost, and the first step is a one-click install from the plugin market or npm. It turned out that Outpost only runs today when installed with `install.sh`, and the user agreed to fix that first. npm publishing waits for now (publishing would make the npm account's email public; the user chose to hold off).

## Why

Installing Outpost directly with `dsh plugin add` (npm, the plugin market and Git all go this way) gets stuck in two places:

1. **No data directory, no start.** The data directory `dataDir` is a required setting, and only the install script writes it into the profile. Someone who installs directly opens Outpost and the plugin does not start.
2. **Without the two browser plugins, all research fails.** The browser fallback is written into Outpost's research preset and needs `@deepseek-ai/dsh-browser-use` and `@deepseek-ai/dsh-experimental-browser-use-playwright-mcp`. The Desktop does not ship them, and they are not in the official 「按需安装」 (install on demand) list either. Without them the research preset does not load, and recommendations, profile building, checks and daily updates all fail at once.

Also, the version number has always been 0.1.0, so the Desktop's 「更新」 (Update) button cannot tell there is a new version.

The community plugin site dsh.so (where the plugin market in the user's Desktop comes from) only lists plugins that "install and load in a blank Desktop", so unless these two are fixed, Outpost cannot get into the market.

## What changed (my calls, agreed by the user)

1. **The data directory has a default: `~/.outpost/data`**, the same place the install script uses. A profile that sets `dataDir` keeps using that; the install script still writes it too.
2. **Without the browser plugins, research still runs, just without a browser.**
   - Outpost carries two research presets: `outpost-researcher` (with a browser, as now) and `outpost-researcher-basic` (no browser, otherwise exactly the same).
   - Before each new research session, Outpost checks whether the one with the browser loads. If it does, it is used; if not (the plugins are not installed, or a Playwright browser opened separately in the profile conflicts with it), the one without the browser is used. Only when neither loads is it 「调研跑不了」 (research can't run).
   - Without a browser, pages that need verification, such as WeChat official accounts (公众号), Xiaohongshu and Zhihu, cannot be opened, and the news about them stays 「待确认」 (unconfirmed), the same as when the browser fallback was turned off before.
   - The top of the settings page says it plainly: 「浏览器兜底没开：桌面版里没装浏览器插件……退出桌面版，在终端运行前哨的一行安装命令，它会把这两个插件一起装上」 (The browser fallback is off: the Desktop doesn't have the browser plugins installed… Quit the Desktop and run Outpost's one-line install command in a terminal; it installs both plugins).
   - Both presets are only for Outpost's research sessions. The user's preset list gains one more entry, 「前哨调研员（无浏览器）」 (Outpost researcher (no browser)), whose description says it is not for manual selection (presets cannot be hidden; the existing one is the same).
   - Sessions with the browser still have `browser_run_code_unsafe` blocked; sessions under the preset without a browser are also treated as research sessions (for example, when the profile opens its own browser, it is blocked there too).
3. **Every release changes the version number.** This one is 0.1.4 (matching m1.4); from now on, each milestone adds one.

## Not done

- No npm publishing (the user is holding off). When it is time to publish to npm, all it takes is: remove `"private": true`, run `npm publish --registry https://registry.npmjs.org` with the user's npm account, then submit to dsh.so.
- The browser plugins are not made dependencies of Outpost: their versions follow the Desktop, and pinning them would break after a Desktop upgrade.
- Outpost does not install plugins for the user (installing a plugin needs the user's own approval).

## How to check

- Unit tests cover: the default directory when `dataDir` is not set; switching to the preset without a browser when the one with the browser is broken; reporting 「调研跑不了」 only when both are broken; the settings page text for the three states.
- On a real machine: in a **separate temporary profile** (leaving the user's Desktop profile and data alone), install Outpost with only `dsh plugin add <package>`, without the browser plugins and without writing `dataDir`, and check that the plugin loads, the settings page shows 「浏览器兜底没开」 (The browser fallback is off), and the data lands in `~/.outpost/data` under the temporary HOME.
