# Outpost M3.4 design: a weekly recap per track

> 2026-11-28. The user chose "search, notes, a weekly recap, step by step, without stopping"; this is the third step. How is my call, summed up under "My calls".

## What the user sees

- **The track page** gets a "Weekly recap" button at its top right (beside "Track settings").
- **The recap page**: titled "Personal Agent · weekly recap", the dates under it ("11-23 – 11-29"; the week still under way is tagged "This week so far"), "‹ Previous week" and "Next week ›" at the top right. From the top:
  - **The AI summary** (tagged "AI summary"): one paragraph of at most 150 characters, first the week's one or two biggest changes, then what the other products were doing. While the week is under way: "Once the week is over, an AI summary is written at the first daily update of the next week (about ¥0.01)".
  - **Findings worth a look**: all the week's "Major" and "Notable" findings (verified or unconfirmed), by importance, then date; each line the product, date, tags and headline, with why it matters under it. Opens the product's Feed scrolled to it. Then "N more minor updates, in each product's Feed".
  - **Dossier changes**: the cards changed in the week: product, dimension, date, with what this version changed. Opens that card, expanded.
  - **Newly profiled**: products whose dossier was first built that week.
  - **Positioning map**: the week's latest summary of the field, and the products that moved since the last drawing before the week (on the same axes). Opens the track page.
  - **Topic updates**: the question, which version, what it changed. Opens the topic page.
  - Last: "Quiet all week: …".
  - With nothing at all: "Nothing new in this track this week."
- **Today's brief**: on the day a recap's summary is written, the brief shows "Last week's recap is out: Personal Agent, 手机 AI 助理" at the top, the names opening them; on a quiet day too.
- **Other chats looking Outpost up** (`outpost_lookup`): a track carries its latest recap's summary (marked the AI's).
- The Runs page has a new kind, "Weekly recap".

## When it is written, and what it costs

- A week runs Monday to Sunday, by the machine's calendar.
- The lists (findings, dossier changes, the map, topics…) are read from the stored data whenever the page opens: **free**, for any week.
- The AI summary is written only for weeks that are over: **after the first daily run of a new week** (brief, maps, weekly suggestions and topics done), last week's summary of each track, when the track existed before last week ended, last week had something to say, and none is written yet. One model call per track, on the brief's model, within the day's budget (none once it is spent); about ¥0.01.
- One that fails on the day (model error, budget) is tried again the next day, until the week after it is over; not after that. A failed run can be retried on the Runs page.

## My calls

1. A week runs Monday to Sunday, by the machine's dates; recaps are per track, with no recap of all tracks together.
2. The lists are not stored but read when the page opens (the data is all there; no second copy to drift); only the AI summary is stored (a new `recaps` table).
3. "Findings worth a look" lists major and notable ones only, minor ones as a count; unproven and withdrawn ones not at all.
4. "Newly profiled" = the product's earliest dossier card was written that week (a new dimension's card added when it joins a second track does not count).
5. "Moved" on the map: compared with the last drawing before the week, on the same axes, by 15 or more on either axis (of -100 to 100); after a change of axes, nothing is compared.
6. The AI summary is written by itself after the first daily run of the new week, with no "write it now" button (once a week and cheap: on time is enough); a failed one can be retried on the Runs page.
7. Ways in: the track page's "Weekly recap" button, and the line on that day's brief; no new row in the middle column, which would add one row per track.
8. Version 0.3.4, tag m3.4; the database goes to version 9 (a new `recaps` table).

## Changed after review (2026-11-28)

The independent review found nothing that blocks the release. Changed:

- **A recap run on the Runs page names its track and week** ("Personal Agent · week of 11-23"); after the track is deleted, "旧赛道 (deleted)".
- **A retry writes the week it was writing**: a recap run keeps the week it writes, so retrying it days later, or retrying a retry, writes the same week; before, it counted back from the retry's day and could write the wrong week, paying again. A manual retry of another week no longer puts off the week due that day. An archived track's recap cannot be retried.
- **The page no longer goes blank while changing weeks**: "Previous week" used to drop the title and the buttons while the new week loaded, losing keyboard focus; now the week shown stays, faded, until the next one is read.
- **"Quiet all week" no longer counts products first profiled that week** (they are under "Newly profiled"); in an earlier week, products not profiled yet (added to the track later) do not show at all.
- **The AI summary words unconfirmed findings as "reportedly" or "not yet confirmed"**, never as settled; the model's instructions said all findings were checked, now corrected.
- Before the new week's first daily run, last week reads "The AI summary is written after this week's first daily update", not that it was not written.
- Only the week's data is read (findings, card versions and topic versions by time range), not every product's whole history each time; other chats looking Outpost up get the latest week's summary (by week, not by when it was written).
- The new tables are created with `IF NOT EXISTS`: going back to an older build and forgetting to reset the version before coming back no longer stops Outpost from starting.

## API and data

- A new table `recaps` (track, the week's Monday, the summary, its run, when it was written), one per track and week, deleted with the track. Database version 9.
- `GET tracks/:id/recap?week=`: the recap of the week that day falls in; without it, last week's, or this week's for a track made this week; a later week is this week.
- `GET brief` gains `recaps`: the recaps whose summary was written that day.
- A new run kind, `recap` (Weekly recap).
- `outpost_lookup` gains `lastWeekRecap` on a track.

Going back to 0.3.3: first `sqlite3 <data dir>/outpost.sqlite 'PRAGMA user_version=8'`, then install the 0.3.3 package (the older build neither reads nor writes the extra table); set it back to 9 before installing 0.3.4 again.
