# Outpost M2.1 design: the track page (comparison table, positioning map, one-sentence summary)

> 2026-11-28. M2 ships in three releases: the track page → weekly suggestions → topics. The user agreed to that order and said "don't stop to wait; record what decisions you made and show me when the tasks are done". The track page's look was chosen by the user on 2026-11-25 (design §5.5, mockup `docs/mockups/5-赛道页.html` option A); what is marked "my call" below I decided while building it.

## What the user sees

- Every track in the middle column (except one still being picked) gets a first row, 「赛道概览」 (Overview), which opens the track page.
- **Header**: the track's name; "n followed · since 11-26 · daily at 08:00 · Looks at: Positioning, Audience, …"; the sentence of what it follows; "Track settings" at the top right (M1.5's edit-track page).
- **One-sentence summary of the field**: a light blue block marked 「AI 归纳」 (AI summary), like the one at the top of today's brief.
- **Positioning map**: two axes, one point per product (icon and name), marked 「推论」 (Inference). Hovering a point says which end it leans to and why; clicking it opens the product. Once the map has been drawn more than once, a product that moved has a dashed circle where it stood the first time and a dashed line to where it is now. "Change axes" and "Redraw" at the top right.
- **Comparison table**: one row per dimension of the track, one column per product of the track (paused ones and ones still being profiled too, marked under their names); each cell is the card's one-line summary. A cell whose card changed today is light blue and marked 「今天」 (Today). Clicking a cell opens the product page with that card expanded. A missing card reads "—", a product still being profiled reads 「建档中」. "Export table" at the top right saves a CSV file (Excel and Numbers open it directly). With many dimensions or products the table scrolls sideways and the dimension column stays put.

## Where the map and the summary come from

- One model call on the brief-writing model (the one that writes the brief's summary), reading each product's card summaries and bullets for the track's dimensions; no web search. Each call is a "Map" run whose cost counts in the daily budget; when the budget is spent, nothing is drawn.
- **When it is drawn** (my call): after each day's brief, each track is looked at; it is drawn again only when it has never been drawn, a product joined or left, or a product's card changed since the last drawing. When nothing changed, nothing is spent. The page can also draw, redraw and change the axes by hand.
- **The axes stay put** (my call): the first drawing has the AI propose two axes; every later one is told to keep them, where each product stood last time, and which products' cards changed since, and to move only those. That way "which way it moved" means something. Only the user changes the axes, and the dashed circles then start again from that drawing.
- **Where the dashed circles count from** (my call): the design says "the position on the day it was profiled", but the products already tracked were profiled before there were maps, so it is "the first drawing on these axes"; the page says "Dashed circles: where they stood on 11-28". A product that moved less than 6 units (coordinates run from -100 to 100) gets no circle, so the map is not covered in small circles.
- **At least two products** (my call): with fewer than two profiled products (tracked or paused, with at least one card of the track's dimensions), there is no map, and the page says why; the table is there anyway.
- An answer that cannot be used (not JSON, a product missing, a summary over 60 characters, an axis end over 12) leaves the map as it was, and the run says so; coordinates out of range are pulled back into -100…100, and a "why" over 40 characters is cut.
- Every drawing is kept (a new table, `landscapes`, database version 5) and deleted with its track; a product that was deleted or left the track is no longer drawn.

## Cost

- A few fen each time: a track of five or six products with six or seven cards each is about 4,000–5,000 input tokens and a few hundred output tokens. Cheaper still in DeepSeek's off-peak hours.
- At most once a day per track (none when no dossier changed), plus the ones drawn by hand.

## My calls (summary)

1. The entry is the first row of each track in the middle column, 「赛道概览」 (the mockup says 「赛道概览 · 对比矩阵」; the column is too narrow, so the short one).
2. The map and the summary use the brief-writing model; no model setting of their own.
3. Redrawn after each day's brief only when a dossier changed; also by hand.
4. The axes stay put and only the user changes them; the dashed circles count from the first drawing on the current axes, and a move under 6 units gets none.
5. No map with fewer than two profiled products.
6. The table lists every product of the track, paused and still-profiling ones included; it exports as CSV (with a byte-order mark, so Excel shows the Chinese correctly).
7. Topics (the block beside the map in the mockup) come in M2.3; this time the map takes the full width.
8. Version 0.2.1 (the first M2 release), tag m2.1.

## API and data

- `GET tracks/:id/overview`: the track, its products in order with their newest card of each of the track's dimensions, the newest drawing, the positions the dashed circles use (`since`), whether a drawing is under way, and how many products can be placed.
- `POST tracks/:id/map` (optionally with `axes`): draws now, in the background; 409 while a drawing is under way, with fewer than two products, or for an archived track.
- Deleting a track whose map is being drawn is a 409 (delete it once the drawing is over).
- New table `landscapes`; a new run kind `landscape` (named "Map" on the Runs page, its subject the track's name, shown as "(deleted)" after the track is deleted).

Going back to 0.1.6: first `sqlite3 <data dir>/outpost.sqlite 'PRAGMA user_version=4'`, then install the 0.1.6 package; the older build neither reads nor writes the extra table. Before installing 0.2.1 again, set it back to 5.

## How it is checked

- Unit tests: the bad answers the parser refuses; kept axes, changed axes, last positions and "recently changed" all in what the model is told; budget, failure, unusable answers; when a redraw is needed; the overview route, the dashed circles, concurrency and refusals; drawing only after the brief, and a failed drawing not keeping the day from completing; the page (table, today's marks, navigation, CSV, map positions, dashed circles, changing the axes, English).
