# Outpost M1.3 design: counting all of the spend

> 2026-11-27. The user asked whether the spend Outpost records is right. It turned out to be undercounted, and the user agreed to fix it. The full investigation is not in the repo; its conclusions are here.

## Why

The spend Outpost showed was wrong in three ways:

1. **Web searches were not counted.** On a DeepSeek route, every `web_search` is a separate model call (`deepseek-v4-flash`, to `api.deepseek.com/anthropic/v1/messages`). DSH keeps the search results and drops that call's `usage`. Outpost only added up the main session's own replies. The 08:00 batch on 11-27 made 191 searches; about ¥0.8–5.4 went unrecorded.
2. **Everything was priced at peak rates.** 08:00 is off-peak, where DeepSeek charges half, so that part was recorded at double its real cost.
3. **「追问」 (follow-up) chats were not counted.** Their usage was never recorded, so they always showed ¥0.

DeepSeek's billing: since 2026-11-18, searches the model makes through a server-side tool have **no per-search fee**. The results count as the model's input tokens. Flash prices per million tokens are ¥2 input, ¥8 output, ¥0.04 cache hit, and half that off-peak. Peak hours are weekdays 9:00–12:00 and 14:00–18:00 Beijing time.

## What changed (my calls, open to change)

1. **Each search is estimated.** Each time DSH sends a search request, it appends a `web/deepseek-search-llm-request` event to the session, and Outpost counts these events. Each search is priced as about 8,000 input and 800 output tokens (`SEARCH_TOKENS`). That is the middle of the range estimated on 2026-11-27, which ran from 3,000/300 to 20,000/2,000 tokens.
2. **DeepSeek routes are priced by time of day.**
   - The Settings price table still holds peak prices; off-peak is halved automatically, and weekends are off-peak all day.
   - Public holidays are not recognised and count as weekdays.
   - Other metered providers get no discount.
   - A run is priced as peak or off-peak as a whole, by **when it started**. A 「追问」 chat is priced reply by reply.
   - When DSH's default model is unknown, the route is treated as DeepSeek, since the price table is DeepSeek's.
3. **「追问」 chats are counted.**
   - Each reply and each search is added to that chat's run and counts towards the day's spend and budget.
   - The budget never blocks a chat, because the user starts it themselves.
   - A chat picked up again on a later day still adds to the day it started.
   - It is priced on the follow-up model set in Settings at the time.
4. **The search count is visible.** Hovering over a cost in 「运行记录」 (Run log) shows 「含 n 次联网搜索，按每次约 8000 输入、800 输出 token 估算」 (includes n web searches, each estimated at about 8,000 input and 800 output tokens).
5. **「再推荐一批」 (Recommend another batch) now says 「约 ¥0.5–1、3–4 分钟」 (about ¥0.5–1, 3–4 minutes).** With searches included, a round costs about ¥0.5 off-peak and about ¥1 at peak. The daily estimate on the new-track page is the average of recent daily runs, so it corrects itself once runs record searches.

## Not done

- **DSH is not changed, so real usage is not available**; DSH drops it. Two ways to get exact figures:
  - switch to DeepSeek's Search API, which bills ¥0.005 per search, so the count is exact;
  - wait for DSH to record search usage.
- **Earlier runs are not recomputed.** Runs from before this change carry no search count and keep the cost they showed.
- **A few small gaps remain** (found in review; each is minor):
  - subagents a 「追问」 chat starts run in sessions of their own and are not counted;
  - when the research model is not DeepSeek, searches go through the DeepSeek Search API (¥0.005 each), which writes no such event, so they are not counted;
  - a search request that fails or is cut off after it was sent still counts once;
  - a 「追问」 chat older than 30 days, reopened, is not counted;
  - one search request may run up to 5 searches inside it, so `SEARCH_TOKENS` is an estimate per request.

## Calibrating later

In a few days, compare with the DeepSeek bill. If it is far off, adjust `SEARCH_TOKENS` (`src/core/cost.ts`).
