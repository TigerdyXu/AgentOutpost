# 前哨 (Outpost) M1.1 design: models set per use, an always-Chinese UI, four acceptance issues

> 2026-11-26. The user's decisions after the M1 acceptance ([`docs/acceptance/m1.md`](../acceptance/m1.md) (Chinese) §5, §9). For the main design see [`docs/en/design.md`](design.md); this document records only the changes.

## Why the change

After M1 was installed in the desktop app, we found that the desktop app's default model is a local Ollama, so follow-up with it times out and cannot answer. The desktop app is in English, so Outpost followed it and showed English. The cross-product acceptance also found 4 more problems (§9.4, items 12–15). The user decided on each item as follows.

## The user's decisions

1. **Models are set separately per use.** Outpost uses a model in four places: research (recommendation, profile building, daily update), fact check, writing the brief summary, and follow-up. Each one can be chosen separately, from all the models currently usable in dsh. These include the local Ollama, the Claude subscription (dsh's built-in 「Anthropic · Claude Pro/Max」 login, which is the same subscription Claude Code uses) and DeepSeek. Follow-up defaults to DeepSeek and no longer uses the desktop app's default model.
2. **The UI always shows Chinese**, and does not follow the desktop app's language.
3. **Browser fallback on** (at 13:3x the user changed their mind: 「open the browser fallback if needed」; this batch of Outpost changes takes priority). To hold down the two costs measured in the M1 acceptance, two things are done together: the browser is given only to Outpost's research sessions as far as possible (put into the `outpost-researcher` preset; whether this works is first tested in the development environment, and if it does not, fall back to turning it on globally); and after each research run that session is released and its browser closes with it, so it no longer piles up to 5 GB in a day.
4. **Fix the problems found in the acceptance**:
   - Item 12: when the brief is filtered by track, the card shows the wrong track name;
   - Item 13: the same product written in a slightly different way is treated as two products;
   - Item 14: when picking candidates, you cannot see that a product is already tracked in another track;
   - Item 15: in the English UI, the budget reason is shown in Chinese. Once the UI is always Chinese, this one goes away by itself.

## Approach

Of the two options, the user chose the first:

- **Set separately per use (chosen)**: the settings page has four dropdowns, and the last three default to 「跟调研一样」 (Same as research). Normally you change just one. When needed, you can have fact check or follow-up use a different model.
- **One model for everything (not chosen)**: the simplest, but follow-up and research cannot use different models.

### The 「模型」 (Models) section of the settings page

```
调研（推荐·建档·日更）  [ DeepSeek · deepseek-flash ▾ ]
核查                    [ 跟调研一样               ▾ ]
写哨报总结              [ 跟调研一样               ▾ ]
追问                    [ 跟调研一样               ▾ ]
```

The labels, from top to bottom: 调研（推荐·建档·日更） (Research (recommend · profile building · daily update)), 核查 (Fact check), 写哨报总结 (Write brief summary), 追问 (Follow-up).

- **Options in the dropdown**: grouped by source. The group name is the provider name that dsh itself gives, and the group holds that provider's models. The list is requested from dsh on the spot (`listProviders` / `listModels`) and is not hard-coded in Outpost.
- **An extra option for 「调研」**: one more item, 「DeepSeek Harness 的默认模型」 (DeepSeek Harness's default model). Choosing it means not setting it separately and using the desktop app's default model.
- **How it is stored in the config file**:
  - The original `model` field still means the research model, so existing configs need no change;
  - Three new fields, `verifyModel`, `briefModel` and `followupModel`; if not filled in, it means "same as research";
  - Like the other settings, a change takes effect on the next call, with no restart.
- **When a stored model cannot be listed right now** (for example, Ollama is not running), it is still shown, with 「当前不可用」 (Currently unavailable) after it, and it is not silently replaced.
- **How to use the Claude subscription**: first add Anthropic in DeepSeek Harness's model settings and log in with Claude Pro/Max. After login it appears in the dropdowns automatically. This section carries one line of hint that explains this step.

### How cost is calculated (my judgment, can be changed)

- **DeepSeek**: estimated from the price table as before, and counted in the daily budget.
- **Local models** (the provider is a local service like Ollama): count as ¥0.
- **Anthropic**: counted as ¥0 as a subscription, and not counted in the budget.
  - The cost: if you use a pay-as-you-go API key, Outpost will not record that money for you. The settings page says this clearly.
- **Other pay-as-you-go providers**: for now estimated at DeepSeek's prices, and marked 「估算」 (estimate).

### Risks

- The Claude subscription has a usage cap, and running the research for several products a day may hit it. If it does, that step counts as failed, and under the existing rule it is retried once that day.
- Anthropic may restrict third-party tools from using the subscription login. dsh ships this login entry, but whether it stays stable over the long term has to be judged by actual testing.

### The UI is always Chinese

- Both the Chinese and the English dictionary are kept. But at registration the Chinese dictionary is filled into both the Chinese slot and the English slot, so when the desktop app's language is English, Outpost still shows Chinese.
- Dates and numbers are also shown in the Chinese format.

### Item 12: the track name on brief cards

- When filtering by one track, the card shows that track's name.
- When not filtering, it lists all the tracks the product is in, separated by 「、」 (the Chinese enumeration comma).

### Item 13: identifying the same product

- **How to compare**: when comparing names and companies, first write them in one standard form and then compare: unify full-width and half-width characters, ignore case, and remove spaces and punctuation.
  - 「千问Go!」 and 「千问Go」 count as one, and 「阶跃 Amoo」 and 「阶跃Amoo」 also count as one.
- **No new duplicates from now on**: when creating a product, look for an existing product by the standardized name and company, and if one is found, use it directly.
- **Duplicate candidates that already exist**: when 「开始跟踪」 (Start tracking) is clicked, if a ticked candidate counts as the same as a product that is already tracked (or paused, or being profiled), that existing product is added into this track. No new one is created, and only the missing dimension cards are filled in.
- **When recommending, tell the Agent which products other tracks already track**: include the names and companies, and require it to copy the original spelling when it recommends those products.

### Item 14: mark products that are already tracked when picking candidates

- When a candidate is already tracked in another track, the card says 「已在〈赛道名〉跟踪 · 只补缺的维度」 (Already tracked in <track name> · only the missing dimensions will be filled in). If that product is paused there, it says 「已在〈赛道名〉暂停」 (Already paused in <track name>) and does not mention filling in dimensions (paused products do not run and do not get cards filled in). Several tracks are joined with 「、」.
- The daily cost estimate at the bottom does not count it, because the same product runs only once a day.

## What we are not doing

- Not removing the English dictionary.
- Not merging the duplicate product rows that already exist in the database. For now they are all just candidates, and handling them at the 「开始跟踪」 step is enough.
- Not distinguishing DeepSeek's peak price from its off-peak price by time of day. The estimate is still at the peak price, so it will run high.

## Left to the implementer to decide

- The exact style of the dropdown: use dsh's color variables and the class-name prefix `op-`, consistent with the existing input boxes on the settings page.
- What to show when the model list cannot be obtained (a provider fails to load): that group shows 「读取失败」 (Failed to load), and the other groups are not affected.
