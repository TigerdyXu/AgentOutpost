# 前哨 M3.3 设计：自己的笔记

> 2026-11-28。用户选了「搜索、笔记、周回顾，一步步连着做」，这是第二步。做法是我的判断，汇总在「我的决定」。

## 用户会看到什么

- **产品页**：标题下面一行「＋ 写笔记：你对这个产品的看法、要盯的事」。点开是一个输入框（最多 2000 字，右下角写着已写几个字），「保存」「取消」。保存后显示成一块浅蓝底的「我的笔记」，带最后改动的日期和「编辑」。
- **每条发现的卡片**（今日哨报、产品的「动态」页）：「追问」旁边多一个「写笔记」（最多 500 字）。写了的笔记显示在卡片下面，同样带日期和「编辑」。
- 编辑时：⌘↩ 保存，Esc 放弃；「删除笔记」或者清空后保存，笔记就没了。保存失败会在输入框下面说原因，写的字还在。
- **搜索**（M3.2）会搜笔记：找到的地方标「我的笔记」，下面是那段话。
- **追问**：开追问对话时，第一条消息里带上你对这个产品和这条发现的笔记，标明「我写的看法，不是来源，不要当事实引用」。
- **其他对话查前哨**（`outpost_lookup`，M3.1）：产品和近 14 天的发现带上 `yourNote`，说明里写明这是用户自己的看法，可以参考，不能当事实引用。
- 不花钱：笔记只存在前哨自己的数据里。

## 我的决定

1. 每个产品、每条发现**只有一份笔记**，可以改，不是一串评论；显示最后改动的日期。
2. 产品笔记最多 2000 字，发现的笔记最多 500 字。
3. 产品笔记放在产品页标题下面（所有页签都看得见）；发现的笔记在卡片里，「写笔记」放在「追问」旁边。
4. **调研和核查从来不读笔记**：笔记是你的看法，不该左右 AI 去找什么、怎么判。搜索、追问、其他对话查前哨会用到，而且都标明是你自己的话。
5. 「删除笔记」不再二次确认：删之前输入框里看得到全文，删掉只影响这一条。
6. 删掉产品时，它的笔记和它所有发现上的笔记一起删掉。
7. 这一版只给产品和发现写笔记；赛道、专题的笔记以后需要再加。
8. 版本 0.3.3，标签 m3.3；数据库升到第 8 版（新表 `notes`）。

## 审阅后改的（2026-11-28）

独立审阅没有发现数据方面的问题（删产品、删赛道、数据库升级、追问消息里带特殊字符都没问题）。按审阅改了面板上的几处：

- **输入法选字时按 Esc 不会再丢掉整段笔记**：以前用中文输入法打字、按 Esc 取消候选词，笔记框会整个关掉、写的字全没了；现在选字时的 Esc 和回车归输入法。
- **字数按「字」算，和后台一致**：以前输入框用浏览器的长度上限，一个表情算两个，250 个表情就打不进去了，计数却写 250/500；现在去掉了浏览器的上限，超了会写「超过 2000 字了，删掉一些再保存」并且不能保存。
- **键盘焦点不再丢**：笔记框关上后，焦点回到「编辑」或「写笔记」；保存失败时光标回到输入框，字还在；保存时输入框只读而不是禁用。「编辑」按钮的读屏名称带上是哪个产品、哪条发现的笔记；字数不再每打一个字就念一遍。
- **在「动态」页保存的笔记，切到别的页签再回来还在**：以前 5 秒内来回切，会显示成旧的，再编辑可能盖掉刚存的。
- 笔记的日期跨年时带上年份；产品笔记在下次读到后台的版本后，以后台为准（另一个窗口改了也看得到）。

留下的：**没保存的草稿，换页（换日期、换页签、打开别的产品）就没了**，不会提示。笔记通常很短，先这样；以后要再加「有没保存的笔记，确定离开？」。

## 接口和数据

- 新表 `notes`（kind 是 product 或 finding、对象的 id、内容、最后改动时间），一个对象一份；数据库第 8 版。
- `POST notes/:kind/:id`（body `{ text }`）写入或删除（空白就删），返回 `{ note }`；超长回 400，没有这个产品或发现回 404。
- `GET products/:id` 多 `note`；`GET products/:id/findings` 和 `GET brief` 多 `notes`（按发现 id）。
- 搜索结果的产品和发现多 `inNote`。

退回 0.3.2：先 `sqlite3 <数据目录>/outpost.sqlite 'PRAGMA user_version=7'`，再装 0.3.2 的包（多出来的表旧版不读也不写）；以后再装 0.3.3 前改回 8。
