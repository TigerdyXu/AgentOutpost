# 前哨 M1.4 设计：不用安装脚本也能装上、跑起来

> 2026-11-27。用户想让更多人知道前哨，第一步是能从插件市场或 npm 一键安装。查下来，前哨现在只有用 `install.sh` 装才能跑，用户同意先修这个。npm 先不发（发包会公开 npm 账号的邮箱，用户选了暂缓）。

## 为什么改

用 `dsh plugin add` 直接装前哨（npm、插件市场、Git 都是这条路），会卡在两处：

1. **没有数据目录就不启动。** 数据目录 `dataDir` 是必填项，只有安装脚本会在 profile 里写上。直接装的人打开前哨，插件起不来。
2. **没装浏览器的两个插件，调研全部失败。** 浏览器兜底写在前哨的调研预设里，要用 `@deepseek-ai/dsh-browser-use` 和 `@deepseek-ai/dsh-experimental-browser-use-playwright-mcp`，桌面版不自带，也不在官方的「按需安装」目录里。缺了它们，调研预设加载不了，推荐、建档、核查、日更都会立刻失败。

另外，版本号一直是 0.1.0，桌面版的「更新」按钮认不出新版本。

社区插件站 dsh.so（用户桌面版里插件市场的来源）只收录「在空白桌面版里装得上、能加载」的插件，所以这两处不修，前哨进不了市场。

## 改了什么（我的判断，用户已同意）

1. **数据目录有默认值：`~/.outpost/data`**，和安装脚本用的同一个地方。profile 里写了 `dataDir` 的照旧用写的那个；安装脚本也照旧写。
2. **没装浏览器插件，调研照样跑，只是不开浏览器。**
   - 前哨带两个调研预设：`outpost-researcher`（有浏览器，跟现在一样）和 `outpost-researcher-basic`（没有浏览器，其余完全一样）。
   - 每次新建调研会话前，先看有浏览器的那个能不能加载；能就用它，不能（插件没装，或 profile 里另开了一个 Playwright 浏览器跟它冲突）就用没浏览器的那个。两个都不能才算「调研跑不了」。
   - 没浏览器时，公众号、小红书、知乎这类要验证的页面打不开，相关消息停在「待确认」，跟以前关掉浏览器兜底一样。
   - 设置页顶上说清楚：「浏览器兜底没开：桌面版里没装浏览器插件……退出桌面版，在终端运行前哨的一行安装命令，它会把这两个插件一起装上」。
   - 两个预设都只给前哨的调研会话用；用户的预设列表里会多一个「前哨调研员（无浏览器）」，描述里写明不供手动选择（预设藏不起来，现在那个也是这样）。
   - 有浏览器的会话照旧拦掉 `browser_run_code_unsafe`；没浏览器的那个预设下的会话也按调研会话对待（例如 profile 自己开了浏览器时，同样拦）。
3. **每次发版换版本号。** 这次是 0.1.4（对应 m1.4），以后每个里程碑加一。

## 不做的

- 不发 npm（用户暂缓）。发 npm 时只需要：去掉 `"private": true`，用用户的 npm 账号 `npm publish --registry https://registry.npmjs.org`，然后到 dsh.so 提交。
- 不把浏览器插件写成前哨的依赖：它们的版本跟着桌面版走，写死会在桌面版升级后对不上。
- 不在前哨里替用户安装插件（装插件要用户自己批准）。

## 怎么验

- 单元测试覆盖：没写 `dataDir` 时用默认目录；有浏览器的预设坏了就换没浏览器的；两个都坏才报「调研跑不了」；设置页四种状态（调研跑不了、浏览器已开、没装浏览器插件、被覆盖关掉）的文字。
- 实机：在一个**单独的临时 profile**（不碰用户桌面版的 profile 和数据）里，只用 `dsh plugin add <包>` 装前哨、不装浏览器插件、不写 `dataDir`，看插件能加载、设置页显示「浏览器兜底没开」、数据落在临时 HOME 的 `~/.outpost/data`。

## 实机结果（2026-11-27 18:28）

- 临时 HOME 里的空白 web profile，只运行 `dsh plugin add dsh-outpost-0.1.4.tgz`，没装浏览器插件、没写 `dataDir`：安装成功，前哨启动，数据库建在临时 HOME 的 `~/.outpost/data`；合成出的配置里两个调研预设都在，没浏览器的那个正好少了浏览器一组。
- 没看到的：前哨的接口要登录，临时环境里没有登录，所以「改用没浏览器的预设」和设置页那句话没在真界面上看到，靠单元测试。用户自己的 `~/.outpost` 没被碰。

## 审阅后留下的小问题（都不挡发版）

- 直接装、没装浏览器插件时，桌面版的预设设置里「前哨调研员」会标红「加载失败」，每次启动日志里也有一条警告。调研不受影响（用的是没浏览器的那个），但 dsh.so 的人工审核可能把它看成「加载失败」。要彻底避免，只能把带浏览器的预设从包里拿出去、改由安装脚本写进 profile；等真要上架时再定。
- 「没装浏览器插件」这句话，在带浏览器的预设因为别的原因加载不了时也会出现（比如用户自己的覆盖写坏了），所以文案写的是「多半是」。
- 默认数据目录按用户算，不按 profile 算：同一个用户的两个 profile 都不写 `dataDir` 又都开着前哨，后开的那个会报「数据目录被另一个前哨进程占用」。
- 测试没覆盖：桌面版重新打开一个用没浏览器预设建的旧会话时，仍按调研会话拦工具（逻辑上是对的，`isResearchAgent` 认两个预设）。
