# 前哨 M1.2 设计：已有赛道添加产品、产品在赛道间移动

> 2026-11-26 14:2x 用户提出：「the existed track should support add new products, and move the existed products to other track」。在 M1.1 装进桌面版之后做。主设计见 `docs/设计文档.md`，M1.1 见 `docs/m1.1-设计.md`。

## 为什么做

现在只有新建赛道的那一刻能挑产品。之后想加一个产品，只能等它碰巧出现在「候选推荐」里。产品也没法从一个赛道换到另一个，比如小豆更适合放在「手机 AI 助理」。

## 用户的决定

1. **加产品，两种方式都要。** 每个赛道下面有一行「＋ 添加产品」，点开后：
   - 如果你知道名字：填产品名，官网可以不填，点「加入并建档」；
   - 如果想让前哨再找：一句话写要求，可以不填，点「再推荐一批」，结果进「候选推荐」，照旧在那里挑。
2. **移动，「移到」和「也加到」两种都要。** 产品页右上角「⋯」菜单里有：
   - 「移到其他赛道…」：从原来的赛道拿掉，放进新的赛道；
   - 「也加到其他赛道…」：两边都保留；
   - 「从「X」拿掉」：只在产品同时属于两个以上赛道时出现。
3. **不变的规矩：**
   - 产品的档案和历史都保留，只补新赛道多出来的维度卡；
   - 一个产品不管在几个赛道里，每天只跑一次。

## 做法

### 按名字加（我的判断，可改）

1. **先查是不是已经在跟踪了。** 把填的名字做统一处理（M1.1 的规则：全角半角统一、不分大小写、去掉空格和标点），和别的赛道里正在跟踪、暂停或建档中的产品比。
   - **恰好对上一个：** 直接把它加进这个赛道，只补缺的卡，不花钱。显示「已在「〈赛道〉」跟踪，直接加进来了 · 只补缺的维度」。
2. **没对上：** 先跑一次很小的「确认产品」任务（约 ¥0.1–0.2、1–2 分钟），让 Agent 核实这个产品确实存在、属于这个赛道，并补全公司、地区、形态、官网和图标。核实通过就自动加入并开始建档，和在「候选推荐」里勾选开始的效果一样。
   - 为什么不直接拿名字建：公司是认定「同一产品」的一半依据；官网和图标也要靠它补齐。
3. **核实没通过：** 产品不存在、已经停了、或者不属于这个赛道时，不加入，原样显示 Agent 给的原因，例如「没加进来：找不到叫这个名字的产品」。
4. **「确认产品」的结果不进「候选推荐」：** 它不算一批推荐，所以不会把你正在挑的那批候选顶掉。

### 再推荐一批

- 用现成的推荐任务，加上你写的那句要求。
- 推荐时 Agent 已经知道哪些产品在跟踪：这个赛道里已在跟踪的，不会再推；别的赛道在跟踪的（M1.1 起），照样可以推，名字和公司照抄已有的写法，候选上标「已在X跟踪 · 只补缺的维度」（在那边暂停的标「已在X暂停」），开始跟踪时直接把那个已有的产品加进这个赛道。
- 推荐正在跑时，按钮变成「正在找…」，并给一个去「候选推荐」的链接。

### 移动

- **「移到」：** 产品只属于一个赛道时，才出现「移到其他赛道…」。
  - 选好目标赛道后，一步完成：加进新赛道，再从原赛道拿掉。
  - 新赛道多出来的维度卡马上补上（和 M1 里加维度、加赛道时一样，会等它正在跑的日更或建档结束）。
- **「也加到」：** 只加进新赛道，不拿掉。
- **「拿掉」：**
  - 不允许拿掉最后一个赛道，会提示「这是它唯一的赛道。不想跟了就用「暂停跟踪」。」
  - 拿掉后，那个赛道独有维度的卡片和历史都保留，只是不再显示。
- **可选的目标赛道：** 除了产品已经在的、以及已归档的赛道以外，所有赛道都可以选。一个都没有时，菜单项不能点，并写「还没有别的赛道」。
- **操作完成后，菜单里给一句结果：** 「已移到「〈赛道〉」」或「已加到「〈赛道〉」」；补了卡的，后面加「 · 补 n 张卡」。

## 不做的

- 不做拖拽：中栏拖产品到别的赛道，留到以后。
- 不做批量移动。
- 「确认产品」不做成「候选推荐」那样的列表。

## 交给实现者自己定的

- 添加页的版式：沿用新建赛道页的样式，类名前缀 `op-`，只用 dsh 的配色变量。
- 菜单里选赛道的方式：可以是二级列表，也可以展开成单选，但要能用方向键、Esc 操作，焦点回到「⋯」按钮，和现有菜单的交互一致。
