# 前哨 M1.1 设计：模型按用途配置、界面始终中文、四个验收问题

> 2026-11-26。M1 验收（`docs/acceptance/m1.md` §5、§9）之后用户的决定；主设计见 `docs/设计文档.md`，本文只写改动。

## 为什么改

M1 装进桌面版后发现：桌面版的默认模型是本机 Ollama，追问用它会超时，答不出来；桌面版是英文，前哨就跟着显示英文；跨产品验收又发现了 4 个问题（§9.4 第 12–15 条）。用户逐项拍板如下。

## 用户的决定

1. **模型按用途分开设。** 前哨用到模型的地方有四处：调研（推荐、建档、日更）、核查、写哨报总结、追问。每处都能单独选，可选的是 dsh 里当前能用的所有模型，包括本机 Ollama、Claude 订阅（dsh 自带的「Anthropic · Claude Pro/Max」登录，也就是 Claude Code 用的那套订阅）和 DeepSeek。追问默认用 DeepSeek，不再用桌面版的默认模型。
2. **界面始终显示中文**，不跟着桌面版的语言走。
3. **浏览器兜底打开**（13:3x 改了主意：「open the browser fallback if needed」，前哨这批修改优先）。为了压住 M1 验收量到的两个代价，同时做两件事：浏览器尽量只给前哨的调研会话用（放进 `outpost-researcher` 预设；能不能行先在开发环境实测，不行就退回全局开）；每次调研做完就释放那个会话，它的浏览器随之关掉，不再一天攒到 5 GB。
4. **修掉验收发现的问题**：
   - 第 12 条：按赛道筛选哨报时，卡片上写错赛道名；
   - 第 13 条：同一个产品名字写法稍有不同，就被当成两个产品；
   - 第 14 条：挑候选时看不出某个产品已经在别的赛道跟踪；
   - 第 15 条：英文界面里，预算原因显示成中文。改成始终中文以后，这一条自然消失。

## 做法

两种方案里，用户选了第一种：

- **按用途分开设（选中）**：设置页有四个下拉框，后三个默认「跟调研一样」。平时只改一个就行；需要时可以让核查或追问用另一个模型。
- **一个模型管全部（没选）**：最简单，但追问和调研没法用不同的模型。

### 设置页「模型」一节

```
调研（推荐·建档·日更）  [ DeepSeek · deepseek-flash ▾ ]
核查                    [ 跟调研一样               ▾ ]
写哨报总结              [ 跟调研一样               ▾ ]
追问                    [ 跟调研一样               ▾ ]
```

- **下拉框里的选项**：按来源分组，组名用 dsh 自己给的提供方名称，组里是该提供方的模型。清单现场向 dsh 要（`listProviders` / `listModels`），不在前哨里写死。
- **「调研」的额外选项**：多一项「DeepSeek Harness 的默认模型」，选它就是不单独设，用桌面版的默认模型。
- **配置文件里怎么存**：
  - 原来的 `model` 字段仍然表示调研模型，已有的配置不用改；
  - 新加 `verifyModel`、`briefModel`、`followupModel` 三个字段，没填就是「跟调研一样」；
  - 和其他设置一样，改完下一次调用就生效，不用重启。
- **存过的模型现在列不出来时**（比如 Ollama 没开），照样显示这个模型，后面标「当前不可用」，不会悄悄换掉。
- **怎么用上 Claude 订阅**：先在 DeepSeek Harness 的模型设置里添加 Anthropic，并用 Claude Pro/Max 登录。登录后它会自动出现在下拉框里。这一节写一行提示说明这一步。

### 花费怎么算（我的判断，可改）

- **DeepSeek**：照旧按价格表估算，计入每日预算。
- **本机模型**（提供方是 Ollama 这类本地服务）：记 ¥0。
- **Anthropic**：按订阅记 ¥0，不计入预算。
  - 代价：如果你用的是按量付费的 API key，前哨不会替你记这笔钱。设置页会写明这一点。
- **其他按量付费的提供方**：暂时按 DeepSeek 的价格估算，并标「估算」。

### 风险

- Claude 订阅有用量上限，一天跑几个产品的调研可能碰到上限。碰上了，那一步就算失败，按现有规则当天重试一次。
- Anthropic 可能限制第三方工具使用订阅登录。dsh 自带这个登录入口，但能不能长期稳定用，要以实测为准。

### 界面始终中文

- 中英两套词典保留。但注册时中文、英文两个位置都填中文词典，所以桌面版语言是英文时，前哨也显示中文。
- 日期、数字的格式也按中文显示。

### 第 12 条：哨报卡片上的赛道名

- 按某个赛道筛选时，卡片写这个赛道的名字。
- 不筛选时，列出这个产品所在的全部赛道，用「、」隔开。

### 第 13 条：同一产品的认定

- **怎么比**：比较名字和公司时，先做统一处理再比：全角半角统一、不分大小写、去掉空格和标点。
  - 「千问Go!」和「千问Go」算一个，「阶跃 Amoo」和「阶跃Amoo」也算一个。
- **以后不再新建重复的**：新建产品时，按统一处理后的名字和公司去找已有的产品，找到就直接用它。
- **已经存在的重复候选**：点「开始跟踪」时，如果勾选的候选和一个已经在跟踪（或暂停、建档中）的产品算同一个，就把那个已有的产品加进这个赛道。不再新建，只补缺的维度卡。
- **推荐时告诉 Agent 别的赛道已经在跟踪哪些产品**：带上名字和公司，并要求它推荐这些产品时照抄原写法。

### 第 14 条：挑候选时标出已在跟踪的产品

- 某个候选已经在别的赛道跟踪时，卡片上标「已在〈赛道名〉跟踪 · 只补缺的维度」。
- 底部的每日花费估算不算它，因为同一个产品每天只跑一次。

## 不做的

- 不去掉英文词典。
- 不合并数据库里已有的重复产品行。它们目前都只是候选，在「开始跟踪」那一步处理就够了。
- 不按时段区分 DeepSeek 的高峰价和闲时价。估算照旧按高峰价，会偏高。

## 交给实现者自己定的

- 下拉框的具体样式：用 dsh 的配色变量，类名前缀 `op-`，跟设置页现有的输入框保持一致。
- 模型清单拿不到时（某个提供方读取失败）怎么提示：这一组显示「读取失败」，不影响其他组。
