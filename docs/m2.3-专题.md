# 前哨 M2.3 设计：专题（跨产品深挖一个问题）

> 2026-11-28。M2 的第三次发布（设计文档 §5.5 右半、§5.6）。用户 2026-11-25 定了「赛道页上有专题」和专题的样子（草图 `docs/mockups/5-赛道页.html` 下方「专题怎么用」）；这次实现时的取舍都是我的判断，汇总在「我的决定」。

## 用户会看到什么

- **赛道页**多一块「专题」（在地图和对比矩阵之间）：列出这个赛道的专题，每行是问题、涉及几个产品、首版日期、「一次性」或「每周更新」、上一版改了什么；正在调研的写「正在深挖…」。最下面「＋ 写一个问题，AI 去深挖」。
- **新专题**：在赛道页上展开一个小表单：问题（≤60 字）、涉及哪些产品（默认全选这个赛道里跟踪中的）、「一次性」或「每周更新」，写明「每次约 ¥1–2：一次调研加一次核查」，点「开始深挖」。
- **专题页**：问题、所属赛道、涉及的产品（点了进产品页）、首版日期、更新方式；结论卡片在前（标题、一句话结论、要点），点「展开」看全文和出处，正文里的 [n] 和档案卡片一样能点开看来源原话；每周更新的有「这一版改了什么」和各版的日期。右上「立即更新」（再深挖一次，花一次的钱）、「⋯」里改更新方式、删除专题。
- **产品页**多一个页签「专题」，列出涉及这个产品的专题。

## 怎么做出来的

- **一次调研会话**（运行记录里叫「专题」）：给它问题、涉及的产品（名称、公司、官网）和它们档案里各维度的结论，要它联网查，交 2–6 张结论卡片：标题（≤20 字）、一句话结论（≤40 字）、1–3 条要点、全文（≤2000 字，每句话用 [n] 标来源）、来源（每个要有原文里逐字的一句引句）、涉及哪些产品；自己的推论要标出来。更新时还给它上一版，只改有变化的地方，最后一句话说这一版改了什么。
- **一次核查会话**（运行记录里叫「专题核查」）：和档案卡片一样的核查员、一样的规则：逐个打开来源找原话，打开了却对不上的来源算作废，只靠作废来源的句子删掉，一个能核实的来源都不剩的卡片整张不要。
- 核查后至少剩一张卡片，才写成新的一版；一张都不剩，这次不出新版，专题页写明「这次没出新版：……」。
- **每周更新的专题**：最新一版满 7 天，在每天哨报、地图、每周推荐之后自动再深挖一次；跳过或失败的第二天再试，每天最多一次（和每周推荐一样）。
- 花费：调研会话和核查会话都算进当天预算，和日更一样排队（同时跑的数量受「同时跑几个产品」限制）。

## 删除和改名

- 删赛道：它的专题一起删，连同专题自己的来源。
- 删产品：从各专题的产品里拿掉；一个产品都不剩的专题删掉。已经写好的卡片原文不改（和档案一样）。
- 产品改名：专题里显示新名字（按产品 id 记的）。

## 我的决定

1. 专题放在赛道页地图和矩阵之间，不放草图里地图的右边（地图要宽才看得清）。
2. 一个专题 1–8 个产品，默认选赛道里所有跟踪中的；问题 ≤60 字。
3. 核查沿用档案卡片的规则和核查员（不新写一套）；「官方」照 M1.6 由核查员判断。
4. 每周更新从最新一版的日期起算 7 天；手动「立即更新」也会往后推。
5. 运行记录里的专题和专题核查不能「重试」，要再跑就在专题页点「立即更新」（重试不知道要接着哪一版）。
6. 版本号 0.2.3，对应 m2.3。
